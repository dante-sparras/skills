# Skills

Agent skills that plan, build, test, review, and land work in a repository.

## Coordination

**Operator**:
The person a run works for. Skills written for a conversation call this person the user, and `triage` calls them the maintainer.
_Avoid_: Owner, end user

**Coordinator**:
The one agent the operator talks to. It makes everything the operator asks for a task, starts a worker for each, and makes sure each one ships. It sends a reviewer to every PR once its checks are green, and it is the only agent that watches CI and merges.
_Avoid_: Orchestrator, main agent

**Task**:
One outcome the operator asked for, or one ticket. One worker carries it, and it lands through one PR when it changes code.
_Avoid_: Unit, job

**Spec**:
The issue that describes one feature: the problem, the solution, the user stories, and the decisions made. `to-spec` writes it, and its tickets are its sub-issues.
_Avoid_: PRD, plan

**Ticket**:
One tracer-bullet slice of a spec, published as an issue that names its blockers. One ticket becomes one task.
_Avoid_: Story, subtask

**Worker**:
A fresh agent the coordinator starts with one task and a brief that opens with `auto-mode/rules.md` and `auto-mode/worker.md`. It sizes the task, then opens a PR for it or splits it into tickets, and fixes what review finds. The operator answers it in its own thread.
_Avoid_: Helper, planner

**Reviewer**:
The agent the coordinator sends to one PR it did not write, with a brief that opens with `auto-mode/rules.md` and `auto-mode/reviewer.md`. It proves the behavior, runs `code-review`, and argues each finding with the PR's worker by message until they agree: the worker fixes it, or the reviewer withdraws it. Then it posts `PASS` or `NO AGREEMENT` on the PR. It runs on the `reviewer` model role.
_Avoid_: Verifier, checker, QA agent

**Verdict comment**:
The comment a reviewer posts on a PR once it and the worker are done: `PASS` or `NO AGREEMENT`, the head SHA, the reviewing model, and whether each finding was fixed or withdrawn. It sits under the AI marker.
_Avoid_: Review, approval

**AI marker**:
The line that opens every comment and issue an agent posts. It starts `> *This was generated by AI`, and tells an agent's words from a person's.
_Avoid_: Disclaimer, signature

**Model role**:
A named pair of models, a default and a backup, that `setup-skills` saves: `implementer`, `reviewer`, or `explorer`. A worker runs on `implementer` and a reviewer on `reviewer`.
_Avoid_: Agent type, profile

**Panel**:
The seats of one `code-review` run, one per model family. A reviewer is its first seat.
_Avoid_: Reviewers, jury

**Follow-up**:
Something worth doing that is outside an agent's task. It goes in the agent's result, and the coordinator files it as an issue.
_Avoid_: TODO, nice-to-have

**Map**:
The issue `wayfinder` keeps for work too big for one session. Its children are decision tickets, each a question to settle, not work to build.
_Avoid_: Roadmap, epic

**Friction**:
What cost a worker time during its task, returned as facts at the end of its result and kept in its PR's agent notes.
_Avoid_: Mistake log, complaints

**Repeat**:
The same friction from two workers, the same finding from two reviewers, or the same correction from the operator twice. A repeat becomes a task for the `correct` skill.
_Avoid_: Pattern, recurring issue

## Verification

**Verification skill**:
A project-local skill, named `verify-<app>`, that launches the real app, drives it the way a user does, and captures evidence. The `create-verification-skill` skill generates one.
_Avoid_: Control skill, verify script, e2e harness

**Feature map**:
The `features/` folder of a verification skill: an index plus one file per user-facing feature, saying how to reach it, how to drive it, and what end state proves it works.
_Avoid_: Test plan, feature list

**Doctor**:
The read-only check in a verification skill that answers whether a running instance is worth driving.
_Avoid_: Health check, preflight

**Evidence**:
What a verification run captures to prove behavior: the action and the resulting state, such as screenshots, transcripts, response bodies, exit codes, and side effects. It survives cleanup.
_Avoid_: Artifacts, output

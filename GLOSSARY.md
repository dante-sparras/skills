# Skills

Agent skills that plan, build, test, review, and land work in a repository.

## The factory

**User**:
The person a run works for.
_Avoid_: Operator, owner

**Factory**:
The T3 Code workflow in `factory/factory.ts` that ships each issue labelled `ready-for-agent`: it starts a worker, sends a reviewer to the PR, and merges once the user has approved it. It also checks each spec once its tickets land, and files a guardrail issue for friction that repeats.
_Avoid_: Pipeline, automation, bot

**Land run**:
The short run that acts on one PR that waits for the user's review: it merges it once they have said go, finishes up after a merge they made by hand, or hands the PR back when its worker is needed again.
_Avoid_: Merge job, watcher

**Task**:
One issue in `ready-for-agent`. One worker carries it, and it lands through one PR.
_Avoid_: Unit, job

**Spec**:
The issue that describes one feature: the problem, the solution, the user stories, and the decisions made. `spec` writes it, and its tickets are its sub-issues.
_Avoid_: PRD

**Ticket**:
One issue that `ticket` files: a tracer-bullet slice of a spec, or a change that fits one PR and has no spec. It names its blockers, and each ticket is a task.
_Avoid_: Story, subtask

**Worker**:
A fresh agent the factory starts with one task and a brief that opens with the factory's `rules.md` and `worker.md`. It builds the task in one PR and argues its reviewer's findings. The user answers it in its own thread.
_Avoid_: Helper, planner

**Reviewer**:
The agent the factory sends to one PR it did not write, with a brief that opens with the factory's `rules.md` and `reviewer.md`. It proves the behavior, runs `review-pr`, and argues each finding with the PR's worker by message until they agree: the worker fixes it, or the reviewer withdraws it. Then it posts `PASS` or `NO AGREEMENT` on the PR. It runs on the `reviewer` model role.
_Avoid_: Verifier, checker, QA agent

**Verdict comment**:
The comment a reviewer posts on a PR once it and the worker are done: `PASS` or `NO AGREEMENT`, the head SHA, the reviewing model, and whether each finding was fixed or withdrawn. It sits under the AI marker.
_Avoid_: Review, approval

**Spec check**:
The run a reviewer makes when a spec's last ticket lands. It proves every user story of the spec on main and returns `PASS` or `GAPS`. Each gap becomes a ticket of the spec.
_Avoid_: Integration review, acceptance test

**AI marker**:
The line that opens every comment and issue an agent posts. It reads `> *This was generated by AI.*`, and tells an agent's words from a person's.
_Avoid_: Disclaimer, signature

**Model role**:
A named pair of models, a default and a backup, that the `factory` skill saves: `worker`, `reviewer`, or `explorer`. A worker runs on `worker` and a reviewer on `reviewer`.
_Avoid_: Agent type, profile

**Panel**:
The seats of one `review-pr` run, one per model family. A reviewer is its first seat.
_Avoid_: Reviewers, jury

**Follow-up**:
Something worth doing that is outside an agent's task. It goes in the agent's result, and the factory files it as an issue in `needs-triage`.
_Avoid_: TODO, nice-to-have

**Brief**:
The task text the factory starts a worker or a reviewer with. An agent brief is a different thing.
_Avoid_: Prompt, instructions

**Agent brief**:
The contract on an issue in `ready-for-agent`, written from one template: what a worker builds from, and the bar its PR is held to. It is the issue's body when a skill files the issue, and a comment when `triage` moves an existing issue there.
_Avoid_: Ticket template, task description

**Friction**:
What cost an agent time during its task, returned in its result as a kind and a target, the repo path or command it is about, and kept in a worker's PR agent notes.
_Avoid_: Mistake log, complaints

**Repeat**:
The same friction, by kind and target, from two runs, or once for a `broken` tool. The factory counts friction as each run ends, and files a repeat as an issue that the `correct` skill fixes.
_Avoid_: Pattern, recurring issue

## Verification

**Verification skill**:
A project-local skill, named `verify-<app>`, that launches the real app, drives it the way a user does, and captures evidence. The `create-verify-skill` skill generates one.
_Avoid_: Control skill, verify script, e2e harness

**Feature map**:
The `features/` folder of a verification skill: an index plus one file per user-facing feature, saying how to reach it, how to drive it, and what end state proves it works.
_Avoid_: Test plan, feature list

**Doctor**:
The read-only check in a verification skill that answers whether a running instance is worth driving.
_Avoid_: Health check, preflight

**Evidence**:
What a verification run captures to prove behavior: the action and the resulting state, such as screenshots, transcripts, response bodies, exit codes, and side effects. It survives cleanup.
_Avoid_: Artifacts, output

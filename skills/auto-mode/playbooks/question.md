### Question

**The deliverable is an answer. The repo stays as it is.**

1. **Trace.** Read the code, the history, or the primary source the question is about. When that is long reading and other tasks are running, give it to an explorer, per **implement**'s worker table. Done when every part of the question has a source that was opened.
2. **Answer.** Tie each claim to a `path:line`, a commit, or a link, and mark what was inferred.
3. **Point on.** If the answer calls for a change, name the playbook that would make it and stop there.

**Reply:** the answer first, then the evidence, then the playbook a follow-up would take.

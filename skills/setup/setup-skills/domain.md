# Domain docs

How the engineering skills read this repo's domain documentation.

## Read before exploring

- **`GLOSSARY.md`** at the repo root, or
- **`GLOSSARY-MAP.md`** at the repo root when it exists. It points to one `GLOSSARY.md` per context: read each one the topic touches.

When neither file exists, carry on without comment. The `domain-modeling` skill creates them when the first term settles.

## Use the glossary's vocabulary

When your output names a domain concept, in an issue title, a refactor proposal, a hypothesis, or a test name, use the glossary's term and stay off the synonyms it lists under `_Avoid_`.

A concept the glossary lacks is a signal. Either you are inventing language the project does not use, so reconsider, or there is a real gap, so note it for `/domain-modeling`.

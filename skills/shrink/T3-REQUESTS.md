# Dispatch model requests

1. Start the worker command as a background shell process. Keep that process open while servicing its request queue. Give each retry a fresh queue directory and the original state directory.
2. Run `python run.py pending --queue <dir>` to list open requests. Use the path to the skill's script when running outside its scripts directory. Keep a ledger from request IDs to T3 task IDs. Dispatch new requests in parallel with `delegate_task` and set `clientRequestId` to the request ID. Use the exact provider, model, and reasoning effort from `seat`. Resolve the reasoning option ID from the local catalog.
3. Give the delegate the request's `instructions` and `prompt` verbatim, with a common instruction to answer directly from the supplied material in its final message. Keep repository paths, cache files, and prior results out of the brief. Ask the delegate to answer without reading files, loading skills, or calling tools. Send the with-skill text only where the request includes it. T3 still supplies its standard harness instructions.
4. Follow T3's continuations. On completion, check the reported provider, model, and options against the seat. Check `executedModel` when T3 reports it. If that field is absent, use the reported configuration and disclose the missing execution metadata in the run report. Write the delegate's final text to a temporary UTF-8 file, then run `python run.py reply --queue <dir> --id <id> --file <path>`. On failure, model substitution, or timeout, cancel any live attempt and use `--error <message>` in place of `--file` when the request remains open. The worker creates a new request for a retry.
5. Read the queue after submitting each reply and dispatch newly available requests. Continue until the worker exits. A successful run prints a JSON summary. Report the worker error if it exits before producing one.
